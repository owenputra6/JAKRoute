# Update Supabase routing + crowd koridor

Perubahan ini mengganti integrasi baca-saja `station_locations` dengan dua sumber
routing sebenarnya:

1. `station_blocks`: 55 Polygon Lantai 2, seluruhnya obstacle keras.
2. `station_nodes`: 18 point routable dan 2 point pembentuk koridor crowd.

Backend sekarang membangun graph dari data tersebut. Point routable menjadi anchor
origin/destination dan dihubungkan ke grid bebas terdekat. Point yang berada sangat
dekat batas block dapat digeser hanya pada koordinat routing menuju titik bebas
terdekat; koordinat sumber tetap dipertahankan untuk tampilan dan audit.

Point 19–20 membentuk koridor selebar 2 m. Simulator membuat tepat 100 user dummy
dengan bobot individual. Bobot area dihitung sebagai jumlah bobot dibagi luas koridor.
Objective `fastest` memakai perlambatan tersebut; `min_walk` tidak mengubah pilihan
jalur karena crowd, tetapi tetap melaporkan estimasi waktunya.

## Urutan pemasangan

1. Jalankan `supabase/01_station_blocks.sql`.
2. Jalankan `supabase/02_station_nodes.sql`.
3. Isi `.env` backend: URL, anon key, dua nama tabel, dan `palmerah` sebagai station ID.
4. Jalankan `scripts/jakroute_setup.ps1` untuk dependency + test.
5. Jalankan `scripts/jakroute_run.ps1` dan Flutter pada terminal terpisah.

SQL tidak menghapus tabel lama. Hapus tabel lama hanya setelah endpoint `/catalog`,
`/crowd/snapshot`, dan `/recommend-route` sudah terbukti memakai dua tabel baru.

## Batas data

GeoJSON belum menyediakan boundary walkable eksplisit. Untuk prototype, backend
membentuk boundary dari convex hull seluruh geometri ditambah margin 1,5 m. Status
ini dikembalikan di katalog dan sebagai warning route. Tambahkan boundary hasil
survei sebelum menyebutnya navigasi operasional.
